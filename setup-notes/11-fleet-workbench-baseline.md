# 机群工作台实施基线

日期：2026-08-05

## 工作边界

- 基于现有 `twin` 分支和提交 `8ca8ec9` 增量实施，不重写已有单机、实时房间、控制权租约和 Crazyflie bridge。
- 保留 `client/config.json`、`server/config.json`、已有运行目录和用户数据；不得在日志或测试输出中打印密钥。
- 新功能先通过浏览器仿真和服务端自动化验证。没有可靠定位、现场隔离和人工确认时，不执行实体多机飞行。
- 每个后续阶段分别记录在 `setup-notes/12-*.md` 至 `setup-notes/15-*.md`。

## 设计基线

机群页面定位为“低空多无人机飞行甲板”。视觉统一使用深海军蓝仪表面板、信号青、安全绿、警示黄和危险红。常驻界面只保留飞行判断所需信息，调试指标进入折叠诊断区。

唯一强调元素为“任务航段条”：停机位、前往目标、任务执行和返航按真实状态点亮，不增加无意义的装饰动画。

## 验证基线

- `cd client && npm run build`：通过，Vite 共转换 547 个模块。
- `cd server && <project-python> -m unittest tests.test_fleet tests.test_fleet_ws -v`：4 项通过。
- 后端测试必须从 `server/` 目录运行；从仓库根目录运行会因为找不到顶层 `tests` 包而失败。
- 本阶段没有启动 FastAPI、OpenClaw、MediaMTX、Crazyflie bridge 或 Radio。

## 已知性能线索

- 当前主包仍有超过 500 kB 的构建警告，后续通过路由/功能动态加载继续拆分。
- Google Maps 加载器既被启动页静态引用，也被连接检查动态引用，因此不会形成独立动态 chunk；地图优化应侧重持久实例和瓦片预热。
- 当前 3D 首屏会等待精细瓦片，后续调整为“粗场景可操作、后台继续细化”。
